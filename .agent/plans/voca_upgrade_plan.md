# 📋 토익 보카 시스템 개선 및 시나공 데이터 통합 계획 (Voca System Upgrade Plan)

본 문서는 시나공 보카 데이터를 기반으로 현재의 보카 시스템을 고도화하고, 체계적으로 데이터를 추출/통합하기 위한 단계별 실행 계획입니다.

## 🎯 최종 목표
- **학습 질 개선**: 단순 뜻 나열에서 벗어나 출제 포인트(Usage), 빈출 숙어(Collocation), 문법 팁(Grammar)이 포함된 실전형 데이터 구축
- **안정적 확장**: 기존의 '주제별 분류'와 '일일 80단어 고정' 체계를 유지하며, 학습 회차를 15일에서 20일로 확장
- **데이터 정합성**: 시나공 보카(Day 1~20) 데이터를 정확하게 추출하고 기존 데이터와 정교하게 병합

---

## 📅 단계별 실행 계획 (7단계)

### [Phase 1] 데이터 추출 및 정합성 확보 (✅ 완료)
- [x] **1.1 시나공 Day 1~20 전수 재추출**: 
    - **결과**: Day 1-20 (총 1,000단어) 이미지 대조 전사 완료 (`toeic-data/sina_voca_day1~20.json`).
    - **원칙 준수**: Zero Paraphrasing, 교재 내 모든 필드(Tip, Grammar, Collocation) 완벽 추출.
- [x] **1.2 데이터 표준화**: 고유 ID(`sina_d{Day}_{No}`) 부여 및 표준 스키마 적용 완료.

### [Phase 2] 데이터 현황 분석 및 전략 수정 (📍 현재 단계)
- [x] **2.1 기존 시스템 분석**: 
    - **발견된 문제**: 기존 `vocabulary_final.json` 및 Firestore 데이터의 심각한 오염 확인 (예: `be` -> `떨뜨리다` 등 매핑 오류).
    - **결정**: 기존 데이터와의 '하이브리드 병합'은 데이터 오염 우려로 인해 **포기**. 
- [ ] **2.2 데이터 교체 전략 (Pivot)**: 
    - **변경 사항**: 기존 UI 구조는 유지하되, 내부 데이터만 새로 전사한 **시나공 1,000단어로 전격 교체**.
    - **이점**: 데이터 신뢰도 100% 확보 및 예문/팁 기반의 고차원 학습 가능.

### [Phase 3] 데이터 정규화 및 이관 (Data Migration)
- [ ] **3.1 필드 정규화 (Mapping)**: 
    - 새 JSON 필드를 기존 UI(`VocabularyWord` 인터페이스)에 맞게 매핑.
    - `exampleMeaning` ➡️ `exampleKo`
    - `exampleTip` ➡️ `usageNote`
    - `grammarPoint` ➡️ 유지 등.
- [ ] **3.2 Firestore 데이터 이관**:
    - 기존 Firestore `vocabularies` 컬렉션 초기화 또는 덮어쓰기.
    - 1,000개 단어 순차 업로드 스크립트 실행.

### [Phase 4] UI 테마 동기화 및 최종 검증
- [ ] **4.1 대시보드 주제 동기화**: `app/homework/voca/page.tsx`의 `DAY_THEMES`를 시나공 실제 목차로 수정.
- [ ] **4.2 UI 렌더링 확인**: `VocabularyCard`에서 시나공 전용 필드(문법 팁 등)가 올바르게 표시되는지 전수 점검.
- [ ] **4.3 학습 기록 보존성 확인**: 단어 교체 후에도 사용자의 `wordStatus` 기록이 정상적으로 유지되는지 확인.

| 구분 | 기존 계획 (Hybrid) | 수정 계획 (Clean Replacement) | 사유 |
| :--- | :--- | :--- | :--- |

| **병합 방식** | 교집합 수동 병합 | **전체 덮어쓰기 (Clean Sweep)** | 데이터 정합성 보장 및 작업 속도 향상 |
| **UI 개편** | 대대적인 구조 변경 고려 | **현 구조 유지, 데이터 필드만 매핑** | 사용자의 요청에 따른 "최소 변동" 원칙 준수 |

## 📐 데이터 교체 원칙 (New Standard)

1. **데이터 신뢰도 우선**: 교재에 없는 내용을 AI가 생성하는 것을 철저히 금지함.
2. **필드 호환성**: 기존 시스템이 사용하는 `VocabularyWord` 인터페이스를 깨지 않는 선에서 데이터를 가공함.
3. **학습 연속성**: 단어 ID 체계를 정교하게 관리하여, 데이터 교체 시에도 기존 학습자들의 진도가 꼬이지 않도록 배려함.
