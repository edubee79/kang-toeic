# 05. 데이터 추출 및 이식 워크플로우 (Extraction Workflow)

본 문서는 원본 소스(이미지)에서 최종 TypeScript 데이터 파일로 변환하는 실전 매뉴얼입니다. 에이전트는 작업 시작 전 본 문서를 반드시 숙지해야 하며, 이를 어길 시 '치명적 실패(Critical Failure)'로 간주합니다.

---

## 🚫 0. 핵심 절대 원칙 (Critical Failure Prevention)

1.  **이미지 최우선 원칙 (Source of Truth)**: 모든 데이터의 유일한 정답은 '원본 이미지'입니다. 텍스트 파일이나 기존 코드의 내용을 맹신하지 마십시오.
2.  **검증 없는 출력 금지 (RRLE_003)**: 이미지를 직접 확인하지 않고 "그럴듯한" 데이터를 생성하는 행위(할루시네이션)는 즉시 퇴출 대상입니다.
3.  **확인 미이행 시 '불충분' 보고**: 이미지를 찾을 수 없거나 대조가 불가능한 경우, 추측하지 말고 즉시 작업을 중단하고 `INSUFFICIENT_DATA`를 보고하십시오.

---

## 🔄 1. 작업 단계 (Image-First Workflow)

1.  **소스 확보 (vFlat/Capture)**:
    *   **PDF 직접 업로드 금지 ❌**: PDF의 텍스트 레이어를 복사-붙여넣기 하면 오타와 할루시네이션이 발생합니다.
    *   **화면 캡처 권장 ⭕**: `Win + Shift + S`를 통해 문제/해설 부분을 **그림 파일**로 확보하십시오. AI가 실제 눈으로 보고 판단하게 해야 합니다.
2.  **AI Vision 주입**:
    *   채팅창에 확보한 이미지를 직접 붙여넣고 데이터 추출을 명령하십시오.
    *   "이미지 1(문제)과 이미지 2(스크립트)를 대조해서 JSON으로 뽑아줘"와 같이 명시적인 시각 대조를 요구하십시오.
3.  **1차 정규화 및 오타 교정**:
    *   추출된 텍스트가 이미지와 **100% 일치**하는지 한 글자씩 대조하십시오.
    *   특히 약어의 마침표(`A.M.`, `P.M.`, `Inc.`), 이메일 주소, 날짜를 집중 확인하십시오.
4.  **기준 기호 부여**: `02_SYMBOL_CODEBOOK` 및 `03_RC_CRITERIA`를 적용하여 태깅(setType, docType 등)하십시오.
5.  **무결성 검증**:
    *   **빌드 체크**: `npx tsc --noEmit`으로 타입 오류 확인.
    *   **UI 체크**: 로컬 환경(`npm run dev`)에서 지문의 가독성 및 스크롤 문제를 직접 확인.

---

## 🛠️ 2. 데이터 정제(Cleanup) 세부 기준

*   **따옴표/기호**: `“ ”` (Smart Quotes) 대신 `" "` (Straight Quotes) 사용.
*   **날짜/시간**: 이미지에 표기된 형태(예: `10:23 A.M.`)를 점 하나 틀리지 않고 100% 동일하게 유지.
*   **고유 명사**: 업체명, 사람 이름의 철자가 영수증/지문 내에서 일치하는지 확인.
*   **줄바꿈**: 지문의 실제 줄바꿈(Paragraph) 구조를 마크다운(`\n\n`)으로 정확히 구현.

---

## ✅ 3. 최종 완료 체크리스트 (Veto Table)

| 항목 | 검증 방법 | 필수 확인 |
| :--- | :--- | :---: |
| **이미지 확인** | **"나는 이 데이터를 작성하기 위해 원본 이미지를 내 눈으로 직접 보았는가?"** | □ |
| **PDF 미사용** | PDF 텍스트 복사가 아닌 이미지 캡처/추출 방식을 사용했는가? | □ |
| **100% 일치** | 대소문자, 약어 마침표, 특수기호가 이미지와 완벽히 일치하는가? | □ |
| **판정 근거** | Q-Type(Inference/Detail 등) 판정 시 질문 속 키워드를 원본과 대조했는가? | □ |
| **구조 무결성** | `setType: "Single"` 등 필수 데이터 형식이 누락 없이 적용되었는가? | □ |
